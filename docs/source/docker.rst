Run Docker directly
=====================

Use the published v1.2.0 image on a Linux Docker host with NVIDIA GPU access for
DL and a FreeSurfer license for surface/atlas processing. The image supplies
the models, FreeSurfer, Convert3D, atlas resources and custom pial tools.
For managed run records and cancellation, see the Python :doc:`quickstart`.

Complete DL, surfaces and atlas merges
----------------------------------------

Edit the paths, choose one contrast and anatomical hemisphere, and select an
available GPU. The output directory must be new; its parent must exist.

.. code-block:: bash

   (
   set -euo pipefail
   INPUT=/absolute/path/inputs
   OUTPUT=/absolute/path/new_results
   LICENSE=/absolute/path/license.txt
   CONTRAST=flash
   HEMI=rh
   GPU=0
   IMAGE=pulks/docker_purple_mri:v1.2.0

   test -d "$INPUT"
   test -s "$LICENSE"
   mkdir "$OUTPUT"
   docker pull "$IMAGE"
   IMAGE_ID=$(docker image inspect --format '{{.Id}}' "$IMAGE")
   printf '%s\n' "$IMAGE_ID" > "$OUTPUT/docker_image_id.txt"

   docker run --rm --gpus "device=$GPU" --shm-size=8g \
     --mount "type=bind,src=$INPUT,dst=/input,readonly" \
     --mount "type=bind,src=$OUTPUT,dst=/output" \
     --mount "type=bind,src=$LICENSE,dst=/license.txt,readonly" \
     --env FS_LICENSE=/license.txt --env NO_FSFAST=1 \
     --env PYTHONUNBUFFERED=1 --env EXVIVO_TIMING_DIR=/output/timings \
     --entrypoint /bin/bash "$IMAGE_ID" \
     /src/commands_nnunet_inference.sh exvivo_dl exvivo_surface \
     --contrast "$CONTRAST" --hemi "$HEMI" --threads 8 \
     --input-dir /input --dl-dir /output/dl \
     --surface-dir /output/surface --atlas-output-dir /output/atlases \
     2>&1 | tee "$OUTPUT/run.log"

   test -f "$OUTPUT/dl/STRUCTURES_COMPLETE"
   test -f "$OUTPUT/surface/COMPLETE"
   test -f "$OUTPUT/atlases/COMPLETE"
   )

Choose ``t2w``, ``ciss``, ``flash`` or ``t2star`` and the actual ``lh`` or ``rh``
hemisphere. Files are named ``SUBJECT_0000.nii.gz``. Surface reconstruction uses
``dl/12_surface_labels`` and the final seven atlas merges are in ``atlases/``.

Stage selection and reuse
---------------------------

For DL only, use ``exvivo_dl`` as the stage and the same explicit paths and
contrast. A license is needed for surface/atlas processing. The compatibility
name ``exvivo_all`` means DL only.

For surface-only processing, mount the complete existing DL root at
``/reuse_dl`` with write access for checkpoints, use ``exvivo_surface``, and set
``--dl-dir /reuse_dl``. Retain the MRI and license mounts, choose fresh surface
and atlas output directories, and omit the GPU option.

For atlas-only reuse, mount the existing DL root at ``/reuse_dl:ro`` and surface
root at ``/reuse_surface:ro``, use ``exvivo_atlas_merge``, and set
``--dl-dir /reuse_dl --surface-dir /reuse_surface``. Point
``--atlas-output-dir`` to a new writable directory. The container checks
surface/projection provenance before merging. The :doc:`quickstart` provides
complete Python CLI commands for these reuse workflows.

Resume a matching direct Docker run by repeating the original container command
with ``--resume`` and the same immutable image ID, inputs, mounts and options.
Reuse the existing output directory and save the new terminal log separately;
do not repeat the initial ``mkdir`` step. The container reuses stages only when
their recorded dependencies and output hashes match.

Final file check
------------------

After a full run, use the checker in the same image. Set ``INPUT``, ``OUTPUT``,
``LICENSE`` and ``IMAGE_ID`` as above (or read the ID from
``OUTPUT/docker_image_id.txt``):

.. code-block:: bash

   docker run --rm \
     --mount "type=bind,src=$INPUT,dst=/input,readonly" \
     --mount "type=bind,src=$OUTPUT,dst=/output" \
     --mount "type=bind,src=$LICENSE,dst=/license.txt,readonly" \
     --env FS_LICENSE=/license.txt \
     --entrypoint /bin/bash "$IMAGE_ID" -c '
       set -e
       source /src/purple_surface_environment.sh
       /surface_env/bin/python /src/check_outputs.py \
         --input-dir /input --output-dir /output
     '

The output bind is writable for the checker's temporary work. This checks files,
grids, hashes, reconstruction mapping and seven atlas merges; anatomical review
is described in :doc:`qc`. Direct Docker execution saves its own log and image
identity; ``purple_run.json`` is generated by the Python CLI.
